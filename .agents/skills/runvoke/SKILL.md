# Runvoke 工作流

在修改 Runvoke 的 Vue 前端、Tauri 配置或 Rust 后端时使用本技能。

## 工作流程

1. 阅读根目录 `AGENTS.md`、`PROJECT_OVERVIEW.md` 和相关实现代码。
2. 保持 Tauri 2、Vue 3、TypeScript、Rust 和 pnpm 的既有技术方案；涉及界面设计时同时读取并遵循 `.agents/skills/runvoke-design-system/SKILL.md`。
3. 进程管理相关改动必须考虑常驻任务重复启动、一次任务并发、临时命令、异常退出、子进程回收、隐藏终端窗口和日志线程。
4. 多任务实现中，任务配置使用 `taskId`，每次执行使用独立 `runId`；状态、日志和停止操作均应面向 `runId`。
5. 根据改动范围运行对应验证命令，并记录未能执行的检查及原因。
6. 修改项目目录选择流程时，验证常见项目清单的名称识别、目录名回退和手工名称不被覆盖。
7. 修改项目目录打开方式时，验证 VS Code 和系统文件管理器命令均会先校验目录存在，并且不会显示终端窗口。
8. 修改预设任务配置时，验证前端、保存命令和读取旧配置均遵守最多 3 条的限制，且运行记录区域不会被任务列表挤出可视范围。
9. 修改运行记录时，验证活动任务卡片可显示状态并经确认停止，且仅非活动实例可单独或一键经确认移除；移除后状态与日志均不会在轮询时恢复。
10. 修改更新或发布能力时，验证稳定更新端点指向阿里云 OSS、更新器权限包含检查/下载/安装、应用启动后及每 30 分钟自动检查、设置中的立即检查入口可用；预览检查必须默认关闭，用户主动开启后才读取独立预览清单，并在发现与安装确认时提示可能不稳定。安装更新前必须二次确认并等待全部活动任务及其子进程回收完成，停止失败或超时不得继续更新；发布工作流必须先上传版本化安装包和签名、最后上传稳定 `latest.json` 或预览 `latest-prerelease.json`，`RELEASE_NOTES.md` 同步到 GitHub Release 与更新清单，安装包签名与 OSS 写入凭据只由 GitHub Secret 提供，且私钥和 AccessKey 不出现在仓库或日志中。
11. 修改项目右键菜单时，验证原生右键菜单被拦截，右键目标项目会选中该项目，点击“编辑”后打开对应配置而非当前已选项目的配置。
12. 修改主题能力时，验证浅色与深色主题中的设置、工作区、表单、运行记录和浮层均具备可读性；重启后主题选择保持，且不影响项目配置、运行状态或日志。
13. 修改日志链接能力时，验证仅识别 HTTP/HTTPS、打开操作使用系统默认浏览器、复制操作具有失败反馈，且点击行为设置可持久化。
14. 修改应用实例行为时，验证第二次启动不会创建额外窗口或托盘图标，且能显示、取消最小化并聚焦已有主窗口。
15. 修改项目排序时，使用 `vue-draggable-plus` 的 fallback 模式，并验证普通列表及搜索结果中的拖拽均可用、占位反馈清晰、持久化失败会恢复原顺序，且重启后保持排序结果。
16. 修改项目分组时，验证创建、重命名、折叠、组内排序、跨组移动和删除分组均可持久化；删除分组只能将项目移到“未分组”。
17. 修改设置能力时，将配置项放在全宽独立设置页；进入设置时隐藏侧栏，返回工作台时恢复，并验证开机启动、主题、日志链接和更新操作行为不变。
18. 修改全局进程操作时，验证项目侧栏的停止全部入口只处理活动运行实例，使用既有 `runId` 停止路径回收完整子进程树，并对停止中、部分失败和等待超时给出明确反馈。
19. 修改首页或设置页分栏时，复用 `ResizableSplitPane.vue`；同时验证鼠标拖拽、键盘方向键、最小宽度、窗口缩放、宽度持久化，以及设置页开关前后的侧栏恢复。
20. 修改 GitHub 仓库入口时，验证其默认显示、设置开关可持久化、图标按钮具备可访问名称，并且仅通过既有 `open_external_url` 打开固定 HTTPS 仓库地址。
21. 修改截断文本时，复用 shadcn-vue 的 Tooltip 组件，并验证项目名称、路径、命令、运行记录、底部状态及菜单文本仅在实际溢出时显示完整内容提示，鼠标和键盘均可触发。
22. 修改项目配置目录入口时，验证设置页可打开由 Rust 固定定位的应用配置目录，前端不传递路径，目录不存在时会创建，且 Windows 下不会显示终端窗口。
23. 未完成的新功能应在 `develop` 集成分支中验证；从 `develop` 创建描述性的 `feature/<功能名>` 分支，只有稳定版本才允许合并至 `main` 并创建正式发布标签。
24. 修改项目导入时，验证 VS Code、Code Insiders、VSCodium 和 Cursor 的工作区记录读取、URI 解码、无效路径过滤、规范化去重、清单勾选与取消、批量保存和导入后不自动执行命令；验证每个导入清单可全局或单项选择用目录名替代探测名称；版本更新后的导入询问只显示一次。
25. 修改本地 MCP 时，验证服务默认关闭且仅监听 `127.0.0.1`、无 Bearer 令牌返回 401、`tools/list` 不含任何删除工具、项目与日志查询不返回环境变量值、导入请求只使用 Agent 显式提交的候选目录并打开独立 Agent 前台勾选清单，不读取或混入 VS Code/Cursor 记录且不触发普通导入流程、更新安装请求保留前台确认，并验证关闭服务后端口已释放。
26. MCP 创建、编辑分组或移动项目后，验证前端同时刷新项目和分组数据；连续批量移动后，侧栏项目总数、每个分组及未分组列表必须完整可见。
27. 修改桌面通知时，保持设置侧栏默认隐藏“测试”入口；验证启动阶段预热固定通知窗口、首条通知通过带接收回执的就绪握手可靠送达、后续通知复用该窗口且关闭只隐藏；确认独立窗口透明、置顶、不占任务栏且不抢焦点，并验证卡片区域可交互、其余透明区域可点击穿透。主窗口最小化、失焦或处于后台时，验证任务结束后固定在右下角按退出码显示成功或失败，且用户主动停止不显示完成通知。连续触发多条通知时最多显示 3 条，每条必须独立计时、暂停、关闭并自动回收，不得因另一条退出而提前消失。验证内部通知堆叠配置默认关闭且持久化，逐条排列与堆叠模式可即时切换，堆叠时点击最上层通知能展开、收起并且独立关闭不误触展开；在主窗口当前显示器的工作区内测试左上、中上、右上、左下、中下、右下六种方位及不同缩放比例，确认深浅主题、进入/退出动画、悬停暂停、自动关闭和减少动态效果均正常。

## 验证清单

```bash
pnpm typecheck
pnpm build
cargo check --manifest-path src-tauri/Cargo.toml
```

- 前端改动至少执行前两项。
- Rust 或 Tauri 后端改动至少执行 Cargo 检查。
- 涉及进程生命周期的改动，在 Windows 上验证常驻任务启动和停止、一次任务完成、临时命令执行、并发运行及子进程回收。
- 涉及更新发布的改动，验证 `.github/workflows/release.yml` 的 tag、版本一致性、签名变量和 Release 附件清单；不在本机或日志中输出私钥。

## 文档同步

当项目需求、范围、技术栈、架构、目录结构、运行方式或验收标准变化时，同步更新：

- `AGENTS.md`
- `PROJECT_OVERVIEW.md`
- `.agents/PROJECT_PROMPT.md`
- `.agents/skills/runvoke/SKILL.md`

仅修改不影响上述内容的实现细节时，应在交付说明中说明无需同步文档的原因。
