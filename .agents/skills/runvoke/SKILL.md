# Runvoke 工作流

在修改 Runvoke 的 Vue 前端、Tauri 配置或 Rust 后端时使用本技能。

## 工作流程

1. 阅读根目录 `AGENTS.md`、`PROJECT_OVERVIEW.md` 和相关实现代码。
2. 保持 Tauri 2、Vue 3、TypeScript、Rust 和 pnpm 的既有技术方案。
3. 进程管理相关改动必须考虑常驻任务重复启动、一次任务并发、临时命令、异常退出、子进程回收、隐藏终端窗口和日志线程。
4. 多任务实现中，任务配置使用 `taskId`，每次执行使用独立 `runId`；状态、日志和停止操作均应面向 `runId`。
5. 根据改动范围运行对应验证命令，并记录未能执行的检查及原因。
6. 修改项目目录选择流程时，验证常见项目清单的名称识别、目录名回退和手工名称不被覆盖。
7. 修改项目目录打开方式时，验证 VS Code 和系统文件管理器命令均会先校验目录存在，并且不会显示终端窗口。
8. 修改预设任务配置时，验证前端、保存命令和读取旧配置均遵守最多 3 条的限制，且运行记录区域不会被任务列表挤出可视范围。
9. 修改运行记录时，验证活动任务卡片可显示状态并经确认停止，且仅非活动实例可单独或一键经确认移除；移除后状态与日志均不会在轮询时恢复。
10. 修改更新能力时，验证更新端点指向 GitHub Releases、更新器权限包含检查/下载/安装、应用启动后及每 30 分钟自动检查、设置中的立即检查入口可用、安装包签名由 GitHub Secret 提供，且私钥不出现在仓库或日志中。
11. 修改项目右键菜单时，验证原生右键菜单被拦截，右键目标项目会选中该项目，点击“编辑”后打开对应配置而非当前已选项目的配置。
12. 修改主题能力时，验证浅色与深色主题中的设置、工作区、表单、运行记录和浮层均具备可读性；重启后主题选择保持，且不影响项目配置、运行状态或日志。

## 验证清单

```bash
pnpm typecheck
pnpm build
cargo check --manifest-path src-tauri/Cargo.toml
```

- 前端改动至少执行前两项。
- Rust 或 Tauri 后端改动至少执行 Cargo 检查。
- 涉及进程生命周期的改动，在 Windows 上验证常驻任务启动和停止、一次任务完成、临时命令执行、并发运行及子进程回收。
- 涉及更新发布的改动，验证 `.github/workflows/release.yml` 的 tag、版本一致性、签名变量和 Release 附件清单；不在本机或日志中输出私钥。

## 文档同步

当项目需求、范围、技术栈、架构、目录结构、运行方式或验收标准变化时，同步更新：

- `AGENTS.md`
- `PROJECT_OVERVIEW.md`
- `.agents/PROJECT_PROMPT.md`
- `.agents/skills/runvoke/SKILL.md`

仅修改不影响上述内容的实现细节时，应在交付说明中说明无需同步文档的原因。
